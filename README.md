# نقشه راه مهندس نرم‌افزار و معمار نرم‌افزار (از صفر تا معمار)

**[English version](README.en.md)** | فارسی

نقشه راه کامل و مرحله‌به‌مرحله‌ی **مهندس نرم‌افزار**، **معمار نرم‌افزار** و **توسعه‌دهنده‌ی دات‌نت (.NET)**؛ از برنامه‌نویسی با C# برای کسی که هیچ چیز نمی‌داند تا طراحی معماری سیستم‌های توزیع‌شده. این نقشه راه یک صفحه‌ی تعاملی است که پیشرفتت را با تیک‌زدن مهارت‌ها نگه می‌دارد.

> **استک:** C# و .NET در بک‌اند، React و Next.js در فرانت‌اند
> **محتوای خود نقشه به زبان انگلیسی است**؛ این README فارسی است تا پیدا کردنش آسان باشد.

## این نقشه راه برای چه کسی است؟

- برای کسی که **از صفر** شروع می‌کند و می‌خواهد **مهندس نرم‌افزار حرفه‌ای** شود.
- برای برنامه‌نویسی که می‌خواهد به **معمار نرم‌افزار** (Software Architect) تبدیل شود و نمی‌داند چه چیزی کم دارد.
- برای هر کسی که دنبال یک **نقشه راه دات‌نت (.NET)** با ترتیب مشخص، از C# و ASP.NET Core تا Docker، cloud و میکروسرویس است.

هدف این است که بدون نیاز به راهنما یا مربی بتوانی فاز به فاز جلو بروی. این یک هدف طراحی است و تضمین نیست؛ اگر جایی گیر کردی، آیتم‌های «Needs» به تو می‌گویند به کدام مهارت قبلی برگردی.

## ویژگی‌ها

- **۱۱ فاز (فاز ۰ تا ۱۰) و ۱۹۵ مهارت** به ترتیب یادگیری.
- **معیار تسلط برای هر مهارت:** هر مهارت یک جمله دارد مثل «می‌توانم X را انجام بدهم». وقتی بتوانی انجامش بدهی، تیکش را می‌زنی، نه وقتی که فقط خوانده‌ای.
- **اولویت‌بندی:** هر مهارت یکی از سه برچسب **Core** (ستون اصلی)، **Important** (بعد از Core) یا **Bonus** (عمق اضافه) را دارد و می‌توانی با فیلتر فقط بخشی را ببینی.
- **پیش‌نیاز (Needs):** کنار مهارت‌های وابسته نوشته شده چه چیزی را باید قبلاً بلد باشی.
- **«Ready for the next phase if»** در پایان هر فاز: چند جمله که می‌گوید کی وقت رفتن به فاز بعد است.
- **یک پروژه‌ی شاخص (Flagship):** یک ایده‌ی واقعی را انتخاب می‌کنی و در همه‌ی فازها همان را گسترش می‌دهی. در پایان یک نمونه‌کار منسجم داری.
- **منابع رایگان و قابل‌کلیک** برای هر بخش، با یک «Start here».
- **ذخیره‌ی پیشرفت در مرورگر** (localStorage) و حالت تاریک و روشن.
- **بدون زمان‌بندی:** عمداً نوشته نشده «چند ماه»؛ بستگی به وقتی دارد که می‌گذاری.

## نقشه راه دات‌نت (.NET)

مسیر .NET در این نقشه شامل این موارد است: C# و OOP و LINQ و async/await، ASP.NET Core (Minimal API، DI، middleware)، Entity Framework Core و SQL، طراحی REST API، JWT و OAuth، SignalR و gRPC، تست با xUnit و Testcontainers، Docker و CI/CD، و در انتها پیام‌رسانی، Polly و الگوهای میکروسرویس در دنیای .NET.

## نقشه راه معمار نرم‌افزار

بخش معماری شامل این موارد است: quality attributes و سناریوی کیفیت (ISO 25010)، stakeholder و concern، UML، مدل‌سازی دامنه، Clean Architecture و Hexagonal، DDD، CQRS و Event Sourcing، C4 و ADR، سبک‌های معماری، Strangler Fig و modernization، سیستم‌های توزیع‌شده، resilience، ارزیابی معماری (ATAM و fitness function)، Build vs Buy، و مهارت‌های ارتباطی معمار.

پوشش این نقشه با منابع استانداردی مثل SWEBOK v4، برنامه‌ی درسی iSAQB CPSA-F، SE2014 و ISO/IEC 25010 مقایسه شده است. این مقایسه یک ارزیابی نویسنده است، نه گواهی رسمی.

## چطور استفاده کنم؟

1. آدرس [Software Architect Roadmap](https://javdanfar.github.io/Software-Architect-Roadmap/ "Open the live roadmap") در مرورگرت باز کن.
2. از فاز ۰ شروع کن و به ترتیب جلو برو.
3. هر مهارت را فقط وقتی تیک بزن که بتوانی جمله‌ی «معیار تسلط»اش را انجام بدهی.
4. اگر نقشه سنگین به نظر می‌رسد، از دکمه‌ی **Core only** استفاده کن.
5. یک پروژه‌ی شاخص انتخاب کن و آن را در هر فاز گسترش بده.

پیشرفتت فقط در همان مرورگر و همان دستگاه ذخیره می‌شود. اگر داده‌های سایت را پاک کنی یا از حالت private استفاده کنی، پیشرفت از بین می‌رود.

## سؤالات پرتکرار

**از کجا شروع کنم؟** از فاز ۰. اگر قبلاً برنامه‌نویسی بلدی، فازهای ۰ و ۱ را سریع مرور کن و هر مهارتی را که معیار تسلطش را داری تیک بزن.

**چقدر طول می‌کشد؟** عمداً زمان‌بندی ندارد. به وقتی بستگی دارد که می‌گذاری و به سابقه‌ات.

**آیا باید همه‌ی مهارت‌ها را بلد باشم؟** نه. اول Core، بعد Important، و Bonus فقط اگر وقت داشتی.

**آیا به فرانت‌اند هم نیاز دارم؟** برای معمار شدن در حد مفهومی بله. اگر فقط بک‌اند می‌خواهی، می‌توانی فاز ۴ را بعد از بقیه انجام بدهی.
