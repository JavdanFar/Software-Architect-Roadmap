Software Engineer to Architect Roadmap

Stack: C# and .NET on the backend, React and Next.js on the frontend. Coverage follows the SWEBOK v4 knowledge areas. It starts from zero knowledge and ends at architect level. Follow the phases in order: each one builds on the previous.

Depth in implementation first, then design, then distributed systems, then decision-making and communication. About 30% reading, 70% building. Each sub-skill has a mastery check: if you can do that sentence, tick the box; if you cannot, you are not done yet. Some items also show a "Needs" line: if you do not know those, go back to them first.

Flagship project: pick one real idea (a booking system, a shop, an expense tracker) and extend that same project in every phase instead of starting a new one each time. You finish with one portfolio piece that shows the whole stack.
Priority of each sub-skill: Core the spine of the path Important learn after the core Bonus extra depth

Working notes

  • Follow the phases in order. Do not skip ahead: each phase ends with a "Ready for the next phase if" box that tells you when to move on.
  • Each section lists one "Start here" resource. Read that first; the other chips are for depth. A sub-skill is done when you can do its mastery check, not when you have read the resource.
  • If a resource feels too hard, check the "Needs" line of the item and go back to that skill. Being stuck usually means a missing prerequisite, not a lack of talent.
  • Write short notes on each design decision you make. Explaining it is how you find out whether you understood it.
  • Default to a modular monolith. Move to microservices only with a concrete reason such as team size, independent scaling or deployment.
  • Treat LeetCode-style practice as optional interview prep. The Algorithms section itself is not optional: it is about understanding complexity and data structures.
  • From Phase 7 on, do a game day for each phase: deliberately break the flagship (kill the database, drop a message, exhaust a thread pool) and observe how the system fails.
